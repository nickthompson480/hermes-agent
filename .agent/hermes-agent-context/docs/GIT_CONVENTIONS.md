# Git Conventions

> **This document is authoritative for all agents working in this project.**
> Read it before making any commits or creating any branches.

Git is a first-class part of the `.agent` system. Commit history, diffs, and
branches are project context — not just version control. A well-structured git
history means any agent can reconstruct what happened on a workstream or mission
without reading every prose file.

---

## Commit Message Format

```
type(SCOPE): short description (≤72 chars)

Optional body — why this change was made, not what (the diff shows what).
Keep lines ≤72 chars.

Refs: WS-001, MISSION-001   ← include all relevant IDs
```

### Types

| Type | When to use |
|------|-------------|
| `feat` | New feature or capability |
| `fix` | Bug fix |
| `refactor` | Code restructure, no behavior change |
| `test` | Adding or updating tests |
| `docs` | Documentation only |
| `chore` | Tooling, config, deps, maintenance |
| `agent` | AI-generated or AI-assisted change |
| `init` | Project or workstream initialization |
| `wip` | Work in progress — **never merge to main** |

### Scope

The scope is the primary WS or MISSION ID driving the commit. Use the most
specific ID available.

| Situation | Scope format | Example |
|-----------|-------------|---------|
| Single workstream | `WS-XXX` | `feat(WS-001): add user auth flow` |
| Mission task | `MISSION-XXX/T-XXX` | `feat(MISSION-001/T-003): scaffold DB schema` |
| Cross-workstream | `WS-001,WS-002` | `refactor(WS-001,WS-002): extract shared utils` |
| Project-wide | `project` | `chore(project): update .gitignore` |
| .agent files only | `agent-context` | `docs(agent-context): update WS-001 work log` |

### Examples

```
feat(WS-001): add JWT authentication middleware

Implemented token validation and refresh logic. Chose JWT over sessions
because this API will be consumed by mobile clients (see WS-001 decisions).

Refs: WS-001

---

agent(MISSION-002/T-007): generate CRUD endpoints for user resource

Auto-generated by Sonnet executing MISSION-002. Reviewed output before commit.

Refs: MISSION-002, WS-003

---

docs(agent-context): write session file and update WS-001 work log

Post-session context update. No code changes.

Refs: WS-001
```

## Branch Strategy

### Branch Types

| Branch | Format | Purpose |
|--------|--------|---------|
| `main` | `main` | Stable, always deployable |
| Workstream | `ws/001-short-name` | Active development on a workstream |
| Mission | `mission/001-short-name` | Autonomous mission execution |
| Hotfix | `fix/short-description` | Urgent fixes directly off main |

### Rules

- `main` is always stable — never commit `wip` here
- Every workstream gets its own branch; merge to `main` when the WS reaches a stable milestone (not necessarily complete)
- Every mission **must** run on a `mission/XXX` branch — this gives Opus or a human a clean diff to review before merging
- Branch names are lowercase, hyphen-separated, max ~40 chars

### Branch Lifecycle

```
# Start a workstream
git checkout -b ws/001-user-auth

# Start a mission (always branch from current main or the relevant ws branch)
git checkout main
git checkout -b mission/002-scaffold-api

# Merge a mission back (after review)
git checkout main
git merge --no-ff mission/002-scaffold-api -m "merge(MISSION-002): scaffold API endpoints complete"
git branch -d mission/002-scaffold-api

# Merge a workstream milestone
git checkout main
git merge --no-ff ws/001-user-auth -m "merge(WS-001): user auth milestone complete"
```

Always use `--no-ff` (no fast-forward) so merge commits preserve branch history as a visible seam in the log.

## Git as Context — Queries for Agents

These commands let an agent reconstruct project context from git history without
reading every prose file. **Run these at session start** for the relevant WS/Mission.

### What happened on a workstream?
```bash
git log --oneline --grep="WS-001"
```

### Full diff of everything done on a workstream?
```bash
git log -p --grep="WS-001"
```

### What files has a workstream touched?
```bash
git log --name-only --pretty=format:"" --grep="WS-001" | sort -u | grep -v '^$'
```

### What has changed since the last session? (on current branch)
```bash
git log --oneline main..HEAD
```

### Review a mission's full diff before merging
```bash
git diff main...mission/002-scaffold-api
```

### What changed in the last N commits?
```bash
git log --oneline -20
git show HEAD         # most recent commit details
```

### Find when a specific file was last changed
```bash
git log --oneline -- path/to/file.py
```

### See all commits by a mission
```bash
git log --oneline --grep="MISSION-002"
```

### Reconstruct what an agent did (agent-authored commits)
```bash
git log --oneline --grep="agent"
```

## .agent File Commits

Changes to `.agent/` files are real commits and part of the history.
This means session files, workstream updates, and mission status changes
are all traceable in `git log`.

**Always commit `.agent/` changes separately from code changes.**
This keeps the context history clean and diffable from the functional changes.

```bash
# After a session — commit context updates separately
git add .agent/
git commit -m "docs(agent-context): write session YYYY-MM-DD and update WS-001, WS-002"

# Then commit any code changes
git add src/
git commit -m "feat(WS-001): implement feature X"
```

## Summary for Agents

1. **Every commit references a WS or MISSION ID** — no orphan commits
2. **Mission execution always runs on a `mission/XXX` branch** — clean diff for review
3. **Workstream branches are `ws/XXX-name`** — merge to main at stable milestones
4. **`.agent/` file changes are committed separately** from code changes
5. **Use `--no-ff` merges** — preserve branch seams in history
6. **Query git at session start** — `git log --grep="WS-XXX"` reconstructs context fast
7. **`wip` commits never land on `main`** — squash or rebase before merging
